# 🚀 پلتفرم یکپارچه (Integrated Platform)

## 📖 تئوری و معماری (Theory & Architecture)

پلتفرم یکپارچه بر پایه‌ی **معماری میکروسرویس** (Microservices Architecture) و **الگوی دروازه‌ی API** (API Gateway Pattern) طراحی شده است. این معماری شامل اجزای زیر است:

1. **دروازه (Gateway)**: یک سرور Node.js که به‌عنوان نقطه‌ی ورودی واحد عمل می‌کند و درخواست‌ها را به سرویس‌های مربوطه هدایت می‌کند.
2. **سرویس‌های مستقل (Services)**: هر سرویس (مانند تبدیل 3D، NLP، فروشگاه و ...) به‌صورت مجزا توسعه و استقرار می‌یابد.
3. **فرانت‌اند یکپارچه (Frontend)**: یک صفحه‌ی واحد که تمام سرویس‌ها را به‌صورت کارت‌هایی نمایش می‌دهد.

این معماری مزایای زیر را به همراه دارد:
- **جداسازی نگرانی‌ها (Separation of Concerns)**: هر سرویس وظیفه‌ی خاصی دارد.
- **مقیاس‌پذیری (Scalability)**: هر سرویس به‌طور مستقل می‌تواند مقیاس‌پذیر شود.
- **قابلیت نگهداری (Maintainability)**: تغییر در یک سرویس تأثیری بر سایر سرویس‌ها ندارد.

## 🏆 دستاوردها (Achievements)

- **معماری میکروسرویس**: پیاده‌سازی الگوی Gateway برای مسیریابی درخواست‌ها.
- **یکپارچه‌سازی ۸ سرویس**: تبدیل 3D، NLP، فروشگاه، مدیریت، شطرنج، المپیک، AI Manager و احتمالات.
- **استقرار مستقل**: هر سرویس به‌صورت جداگانه در Vercel مستقر شده است.
- **داشبورد پویا**: لیست سرویس‌ها به‌صورت پویا از `config.js` خوانده می‌شود.
- **قابلیت گسترش**: با اضافه کردن یک سرویس جدید، فقط کافی است آن را به `config.js` اضافه کنید.

## 🧩 چالش‌ها (Challenges)

- **هماهنگی بین سرویس‌ها**: مدیریت نسخه‌های مختلف و وابستگی‌های بین سرویس‌ها.
- **مدیریت خطاها**: اگر یک سرویس از کار بیفتد، کل پلتفرم نباید از کار بیفتد.
- **اتصال به Vercel**: محدودیت‌های Vercel در اجرای سرورهای طولانی‌مدت.
- **تداخل مسیرها**: مسیریابی در Gateway نیاز به دقت دارد تا با مسیرهای سرویس‌ها تداخل نکند.

## ⚠️ محدودیت‌ها (Limitations)

- **عدم پشتیبانی از WebSocket**: Vercel از اتصالات طولانی‌مدت پشتیبانی نمی‌کند.
- **محدودیت زمان اجرا**: توابع Vercel حداکثر ۱۰ ثانیه زمان اجرا دارند.
- **محدودیت حافظه**: حداکثر ۱ گیگابایت حافظه برای هر تابع.
- **نیاز به استقرار جداگانه هر سرویس**: هر سرویس باید به‌طور جداگانه در Vercel مستقر شود.

## 📋 نیازمندی‌ها (Requirements)

- **Node.js 16+**: برای اجرای Gateway.
- **حساب Vercel**: برای استقرار سرویس‌ها.
- **آشنایی با Git و GitHub**: برای مدیریت مخزن.
- **مرورگر مدرن**: برای نمایش داشبورد.

## 🚧 موانع (Obstacles)

- **محدودیت‌های شبکه**: دسترسی به GitHub و Vercel در برخی مناطق محدود است.
- **پیچیدگی راه‌اندازی**: نیاز به استقرار چندین سرویس جداگانه.
- **مدیریت وابستگی‌ها**: ممکن است سرویس‌ها به کتابخانه‌های مختلفی نیاز داشته باشند.

## 🔧 نیازمندی‌های فنی (Technical Requirements)

- **Node.js**: برای Gateway و برخی سرویس‌ها.
- **Python**: برای برخی سرویس‌ها (مانند NLP).
- **npm/yarn**: برای مدیریت بسته‌های Node.js.
- **Git**: برای کنترل نسخه.
