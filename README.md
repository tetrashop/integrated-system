# 📦 داشبورد یکپارچه (Integrated Dashboard)

## 📖 تئوری و معماری (Theory & Architecture)

این پروژه یک **سیستم یکپارچه‌سازی** (Integration System) است که هدف آن جمع‌آوری و نمایش تمام سرویس‌های مستقر در یک صفحه‌ی واحد می‌باشد. معماری این سیستم بر پایه‌ی **نمایش استاتیک** (Static Rendering) طراحی شده است که از سه لایه تشکیل شده است:

1. **لایه‌ی نمایش (Presentation Layer)**: شامل فایل‌های HTML، CSS و JavaScript که رابط کاربری را تشکیل می‌دهند.
2. **لایه‌ی پیکربندی (Configuration Layer)**: فایل `config.js` که لیست سرویس‌ها را به‌صورت آرایه‌ای از اشیاء نگهداری می‌کند.
3. **لایه‌ی استقرار (Deployment Layer)**: فایل `vercel.json` که تنظیمات استقرار در Vercel را مشخص می‌کند.

مهم‌ترین اصل معماری این پروژه **عدم وابستگی به سرور** (Serverless) است که باعث می‌شود در هر محیط میزبانی استاتیک (مانند Vercel، Netlify و GitHub Pages) قابل اجرا باشد. داده‌های سرویس‌ها به‌صورت استاتیک در `config.js` ذخیره می‌شوند و نیازی به پایگاه داده یا API ندارند.

## 🏆 دستاوردها (Achievements)

- **یکپارچه‌سازی**: گردآوری تمام سرویس‌های پراکنده در یک داشبور واحد.
- **استقرار سریع**: با استفاده از Vercel، هر تغییر به‌صورت خودکار deploy می‌شود.
- **قابلیت گسترش**: با اضافه کردن یک شیء جدید به آرایه‌ی `SERVICES_CONFIG`، سرویس جدید به داشبورد اضافه می‌شود.
- **واکنش‌گرایی (Responsive)**: سازگاری کامل با دستگاه‌های مختلف (موبایل، تبلت، دسکتاپ).
- **بدون نیاز به سرور**: کاهش هزینه‌ها و پیچیدگی‌های مدیریت سرور.
- **تست صحت سرویس‌ها**: فقط سرویس‌هایی که پاسخ HTTP 200 می‌دهند در لیست قرار می‌گیرند.

## 🧩 چالش‌ها (Challenges)

- **مدیریت نسخه‌های مختلف**: هماهنگی بین شاخه‌های مختلف (main, integrated-platform, ...).
- **تداخل با کش مرورگر**: گاهی اوقات تغییرات جدید در `config.js` به‌روز نمی‌شوند و کاربر نسخه‌ی قدیمی را می‌بیند.
- **خطاهای استقرار در Vercel**: گاهی به‌دلیل تنظیمات نادرست `vercel.json` یا وجود فایل `index.html` اضافی در ریشه، خطای ۴۰۴ رخ می‌دهد.

## ⚠️ محدودیت‌ها (Limitations)

- **عدم پویایی**: برای افزودن سرویس جدید باید کد تغییر کند و دوباره deploy شود.
- **عدم امنیت**: اطلاعات سرویس‌ها در سمت کلاینت (مرورگر) قابل مشاهده است.
- **عدم پشتیبانی از احراز هویت**: برای دسترسی به سرویس‌های خصوصی نیاز به راه‌حل‌های اضافی است.
- **نیاز به به‌روزرسانی دستی**: اگر آدرس یک سرویس تغییر کند، باید `config.js` دستی ویرایش شود.

## 📋 نیازمندی‌ها (Requirements)

- **مرورگر مدرن**: پشتیبانی از ES6، fetch API و CSS Grid.
- **دسترسی به اینترنت**: برای بارگذاری سرویس‌های خارجی.
- **حساب Vercel**: برای استقرار و مدیریت پروژه.
- **Git**: برای کنترل نسخه و همکاری تیمی.

## 🚧 موانع (Obstacles)

- **محدودیت‌های شبکه**: در برخی کشورها دسترسی به GitHub و Vercel با محدودیت مواجه است.
- **فیلترینگ**: گاهی سرویس‌های میزبانی در ایران قابل دسترس نیستند.
- **عدم آشنایی با Git**: برای کاربران غیرفنی، کار با شاخه‌ها و commit‌ها دشوار است.
- **خطاهای ۴۰۴ و ۵۰۰**: ممکن است به‌دلیل تنظیمات نادرست یا تغییر آدرس سرویس‌ها رخ دهد.

## 🔧 نیازمندی‌های فنی (Technical Requirements)

- **Node.js**: برای اجرای اسکریپت‌های محلی (اختیاری).
- **Git**: برای کلون و مدیریت مخزن.
- **Vercel CLI**: برای استقرار از خط فرمان (اختیاری).
- **مرورگر Chrome/Firefox/Safari**: نسخه‌های اخیر.
