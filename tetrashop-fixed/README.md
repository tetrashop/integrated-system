# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some ESLint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Babel](https://babeljs.io/) (or [oxc](https://oxc.rs) when used in [rolldown-vite](https://vite.dev/guide/rolldown)) for Fast Refresh
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/) for Fast Refresh

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the ESLint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and [`typescript-eslint`](https://typescript-eslint.io) in your project.

## چکیده

پروژه‌ی **تتراشاپ** یک پلتفرم تحت وب چندمنظوره است که با استفاده از کتابخانه‌ی React و ابزار ساخت Vite توسعه یافته است. این سامانه خدماتی نظیر فروشگاه آنلاین، تبدیل تصاویر دوبعدی به مدل‌های سه‌بعدی و بازی شطرنج را ارائه می‌دهد.  
در نسخه‌ی اولیه، چندین نقص فنی (باگ) در بخش رندر، پیکربندی زبان فارسی و وابستگی‌های build وجود داشت که منجر به خطای زمان اجرا، نمایش ناقص رابط کاربری و شکست فرایند تولید خروجی می‌شد. در این مخزن، تمام این اشکالات شناسایی، تحلیل و به‌طور کامل برطرف گردیده‌اند و یک اسکریپت خودکار برای بازتولید فرایند اصلاح نیز ارائه شده است.

---

## ۱. مقدمه

امروزه پلتفرم‌های چندسرویس که از فناوری‌های مدرن رابط کاربری مانند React بهره می‌برند، نیازمند نگهداری دقیق و رعایت استانداردهای بین‌المللی (همچون پشتیبانی از زبان‌های راست‌به‌چپ) هستند. پروژه‌ی تتراشاپ با هدف ارائه‌ی یک فروشگاه اینترنتی به همراه سرویس‌های جانبی تفریحی و گرافیکی طراحی شده، اما به دلیل برخی اشکالات در کامپوننت‌های اصلی و پیکربندی، نسخه‌ی اولیه‌ی آن به‌درستی اجرا نمی‌شد.  
در این گزارش، ابتدا معماری کلی پروژه معرفی می‌گردد، سپس هر یک از باگ‌های شناسایی‌شده به همراه روش اصلاح آن‌ها شرح داده می‌شود.

---

## ۲. معرفی و امکانات پروژه

**تتراشاپ** یک برنامه‌ی تک‌صفحه‌ای (SPA) است که از مسیرهای مختلف (subdomain routing) برای دسترسی به ماژول‌های زیر استفاده می‌کند:

- 🛒 **فروشگاه آنلاین:** نمایش محصولات، سبد خرید و مدیریت سفارشات.
- ♟️ **بازی شطرنج:** یک صفحه‌ی شطرنج تعاملی با قابلیت بازی دو نفره یا مقابل هوش مصنوعی.
- 🔄 **تبدیل ۲D به ۳D:** بارگذاری تصاویر دو بعدی و تولید مدل‌های سه‌بعدی با استفاده از کتابخانه‌های گرافیکی.
- 🌐 **صفحه‌ی فرود اصلی:** شامل پیوند به زیرسامانه‌ها و نمایش اطلاعات کلی.

فناوری‌های اصلی به‌کار رفته:
- **React 18** با ساختار کامپوننتی
- **React Router** برای مدیریت مسیرها
- **Vite** به‌عنوان ابزار ساخت سریع
- **CSS Modules** برای استایل‌دهی
- کتابخانه‌های جانبی مانند Three.js (برای تبدیل ۳D) و chess.js

## ۳. ساختار فنی پروژه

ساختار پوشه‌های اصلی (پس از اصلاح) به شکل زیر است:

```

tetrashop-main/
├── public/
│   ├── 3d-app/         # برنامه‌ی تبدیل ۲D به ۳D (کامپایل‌شده)
│   └── ...
├── src/
│   ├── components/     # کامپوننت‌های React شامل ServicePlatform
│   ├── App.jsx         # کامپوننت ریشه (اصلاح‌شده)
│   ├── main.jsx        # نقطه‌ی ورود برنامه (اصلاح‌شده)
│   └── index.css       # استایل‌های سراسری
├── index.html          # فایل HTML اصلی با تنظیمات فارسی
├── package.json
└── vite.config.js

```

مدیریت مسیرها از طریق کامپوننت `ServicePlatform` انجام می‌شود که بر اساس subdomain یا مسیر URL، ماژول مناسب را بارگذاری می‌کند.

## ۴. تحلیل باگ‌ها و روش‌های اصلاح

طی بررسی نسخه‌ی اولیه، چهار دسته نقص عمده شناسایی گردید:

### ۴.۱. خالی بودن کامپوننت `App.jsx`
**مشکل:** فایل `App.jsx` صرفاً یک `div` بدون محتوا برمی‌گرداند و هیچ کامپوننتی را رندر نمی‌کرد.  
**علت:** احتمالاً در فرایند توسعه، محتوای اصلی حذف یا کامنت شده بود.  
**اصلاح:** کامپوننت `ServicePlatform` که وظیفه‌ی مسیریابی و نمایش زیرسامانه‌ها را دارد، به‌عنوان فرزند `div` اصلی اضافه گردید.

### ۴.۲. نادرستی نحوه‌ی رندر در `main.jsx`
**مشکل:** از API قدیمی `ReactDOM.render` (مربوط به React 17) استفاده شده بود که با نسخه‌ی ۱۸ ناسازگار است و خطای زمان اجرا ایجاد می‌کرد.  
**علت:** عدم تطابق نسخه‌ی React با شیوه‌ی رندر.  
**اصلاح:** کد به `ReactDOM.createRoot(document.getElementById('root')).render(...)` تغییر یافت و کامپوننت `App` درون `React.StrictMode` قرار گرفت.

### ۴.۳. عدم پشتیبانی از زبان فارسی و راست‌به‌چپ
**مشکل:** در فایل `index.html`، ویژگی‌های `lang="fa"` و `dir="rtl"` برای تگ `<html>` تعیین نشده بود.  
**علت:** غفلت در بین‌المللی‌سازی رابط کاربری.  
**اصلاح:** این دو ویژگی به‌طور خودکار توسط اسکریپت اصلاح‌گر به فایل HTML اصلی و نسخه‌ی build اضافه شدند.

### ۴.۴. خطای `terser` در هنگام ساخت (build)
**مشکل:** هنگام اجرای `npm run build` خطای مربوط به عدم وجود ماژول `terser` رخ می‌داد.  
**علت:** Vite برای فشرده‌سازی نیاز به بسته‌ی `terser` دارد که در `devDependencies` ذکر نشده بود.  
**اصلاح:** وابستگی `terser` با دستور `npm install --save-dev terser` به پروژه افزوده گردید.

### ۴.۵. فایل‌های پشتیبان و قدیمی مزاحم
**مشکل:** فایل‌های `App.js` (نسخه‌ی قدیمی غیر JSX) و `App.jsx.backup` در پوشه‌ی `src/` باقی مانده بودند که باعث سردرگمی و احتمال فراخوانی اشتباه می‌شدند.  
**اصلاح:** این فایل‌ها حذف شدند.

## ۵. اسکریپت خودکار رفع باگ (`fix.js`)

برای بازتولید خودکار فرایند فوق، اسکریپتی به زبان Node.js تهیه شده است که مراحل زیر را انجام می‌دهد:
1. کلون کردن یا به‌روزرسانی مخزن اصلی.
2. تحلیل هدف پروژه (فروشگاهی/چندسرویس).
3. اعمال اصلاحات روی `App.jsx` و `main.jsx`.
4. افزودن ویژگی‌های فارسی به `index.html`.
5. حذف فایل‌های اضافی.
6. نصب وابستگی‌ها (شامل `terser`).
7. اجرای لینتر و بیلد نهایی.

این اسکریپت در مخزن جداگانه‌ای به آدرس [tetrashop/tetrashop-fix](https://github.com/tetrashop/tetrashop-fix) نیز موجود است.

## ۶. راهنمای نصب و اجرا

### پیش‌نیازها
- Node.js نسخه ۱۸ یا بالاتر
- npm نسخه ۹ یا بالاتر
- دسترسی به اینترنت برای دریافت وابستگی‌ها

### مراحل نصب
```bash
# کلون کردن نسخه‌ی اصلاح‌شده
git clone https://github.com/tetrashop/tetrashop-fixed.git
cd tetrashop-fixed/tetrashop-main

# نصب وابستگی‌ها
npm install

# اجرای محیط توسعه
npm run dev
```

پس از اجرا، پروژه روی http://localhost:3000 قابل دسترسی خواهد بود.

ساخت نسخه‌ی تولید

```bash
npm run build
```

خروجی در پوشه‌ی dist قرار می‌گیرد.
